# Tickler — Graph Data Model

Tickler stores everything in FalkorDB: lease documents, extracted clauses with verbatim quotes, computed deadlines, reminder state, agent memory, and drafts. There is no second database — removing FalkorDB removes the product.

## Why a graph

The agent's core job is answering questions whose answers depend on relationships: *"Why is this reminder set for March 1?"* means walking reminder → deadline → clause → quote → page and quoting the exact sentence that caused it. *"What's due this month?"* joins leases, deadlines, and reminder state. These are traversals, not filtered lists, so the context layer is a graph and every agent tool is a Cypher query.

## Nodes

| Label | Properties | Written by |
|---|---|---|
| `Lease` | id, title, status, uploadedAt | ingestion |
| `Page` | idx, text | ingestion |
| `Party` | name, role | extraction |
| `Clause` | type, status | extraction |
| `Quote` | text, pageIdx, charStart, charEnd | extraction |
| `Field` | key, value, confidence, approved | extraction → review |
| `Deadline` | date, type, needsReview, reason | computation |
| `Reminder` | leadDays, fireAt, state | Temporal |
| `Alert` | level, message, createdAt | Watcher agent |
| `Draft` | kind, body, status | Drafter agent |
| `Correction` | before, after, at | review UI |
| `Memory` | kind (semantic/episodic/procedural), content, updatedAt | Concierge |
| `Session` | startedAt, userId | Concierge |

## Edges

```
(Lease)-[:HAS_PAGE]->(Page)
(Lease)-[:HAS_PARTY]->(Party)
(Lease)-[:HAS_CLAUSE]->(Clause)
(Clause)-[:GROUNDS]->(Quote)
(Quote)-[:FROM_PAGE]->(Page)
(Clause)-[:YIELDS]->(Field)
(Clause)-[:DERIVES]->(Deadline)
(Deadline)-[:FOR]->(Lease)
(Deadline)-[:SCHEDULED]->(Reminder)
(Alert)-[:ABOUT]->(Deadline)
(Alert)-[:TRIGGERED]->(Draft)      // Watcher → Drafter handoff, state in the graph
(Draft)-[:CITES]->(Quote)
(Correction)-[:EDITS]->(Field)
(Session)-[:ABOUT]->(Lease)
(Memory)-[:ABOUT]->(Lease)
```

## Invariants (enforced in code, not prompts)

1. Every `Quote.text` is a verbatim substring of its `Page.text`. Validated at write time.
2. `Deadline.date` values are computed in code from approved clause fields — never generated by the model.
3. Drafts are always born `pending`; only a human approval moves them forward.
4. Removal test: with FalkorDB down, upload, review, reminders, chat, and drafts are all gone. The app is a shell.

See `docs/cypher.md` for the queries the product depends on.
